# Agent Note：恢复和回收期间保留所有权无法证明的 Harness 路径

Status: implemented

[English](2026-09-23-managed-harness-gc-ownership.md) | 中文

## 问题

Harness 恢复和保留逻辑过去会把路径名称或可复制的所有权标记当成递归删除目录的充分依据。重装期间若在目标目录与备份目录之间崩溃，也可能丢失旧的 current 路径。

## 决策

pending 事务记录 transaction ID、持久化阶段，以及（替换已有安装时）旧安装 ID。恢复过程只会处理标记与 journal 匹配的路径。若 journal 表明存在旧安装，但目标和该事务的备份都无法证明其身份，恢复会保留 journal、阻止新变更，并且不提供启动路径。

没有 transaction ID 的旧 pending 记录会原样保留并写入诊断信息。若记录的 current 安装仍有效，可以继续只读启动。缺少新可信所有权标记的旧 current 安装不能原地重装；Desktop 会说明缺少所有权证明，同时保留启动能力。仍可将较新的不同版本安装到空目标，并保留旧版本用于回滚。

垃圾回收不会删除未被 state 引用的版本目录。完整安装目录和所有权标记都可以被复制成手动备份，因此它们不足以证明目录可丢弃。应用会记录看起来由 Desktop 管理的孤立版本以及未知条目，并保留两者。事务 staging、健康检查目录和替换备份使用独立 transaction ID，只有 journal 与标记匹配时才清理。健康检查 home 位于独立兄弟目录，不会进入最终程序目录。恢复或变更前，Desktop 会检查 managed 路径和现存祖先是否含符号链接或 reparse point。

## 考虑过的替代方案

**删除 SemVer 名称、manifest 和 package 都匹配的孤立目录。** 不采用，因为用户可以把完整版本目录和标记复制为备份。

**清除旧 pending 记录，并猜测固定名称备份的归属。** 不采用，因为旧 state 没有事务身份；固定名称路径可能是用户数据。

**重装前自动迁移没有标记的 current 安装。** 不采用，因为 Desktop 无法证明准确目标归属，迁移需要替换或修改该目录。

## 影响

未知路径和未引用版本可能占用更多磁盘空间，这是有意选择的安全取舍。旧 current 版本仍可启动，安装不同的新版本也仍可继续。没有标记的 current 版本执行同版本重装时会失败，并清楚说明所有权原因。预期备份缺失时，应用会阻止启动和变更，等待检查或修复 state。
